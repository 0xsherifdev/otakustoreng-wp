OTAKU STORE NG — FIX: checkout stopped adding the delivery fee (Aug 2, 2026)
=============================================================================
Symptom: at checkout the Order summary showed only Subtotal and Total — NO shipping
row at all, for EVERY destination (Lagos, other NG states, Ghana, international).
The Lagos LGA dropdown still appeared and still listed the correct prices, but picking
an LGA changed nothing. Total always equalled Subtotal.

STATUS: FIXED. Root cause = a stale WooCommerce cache entry, NOT the zones, NOT the
Lagos LGA snippet, NOT the Minimog theme, NOT Terminal Africa.


=============================================================================
ROOT CAUSE
=============================================================================
WooCommerce's WC_Cart::needs_shipping() begins with a short-circuit:

    if ( ! wc_shipping_enabled() || 0 === wc_get_shipping_method_count( true ) ) {
        return false;          // <-- the whole shipping system is skipped
    }

wc_get_shipping_method_count() does NOT count the zone methods on every request — it
caches the number in a transient, validated against a "shipping" transient version.
That cached number had gone stale at 0. WooCommerce therefore believed the store had
zero shipping methods and skipped shipping entirely:

  - needs_shipping()  -> false
  - no shipping package was ever built, so no zone was ever matched
  - no shipping row rendered on cart or checkout
  - the "Ship to a different address?" checkbox disappeared (it is gated on the same
    call) — this is the easiest visual canary
  - it failed identically for Lagos, Oyo, Ghana and the USA, which is what proved the
    cause was global rather than zone- or snippet-specific

The admin screens all looked perfectly healthy the whole time — all 7 zones present,
every method enabled — because the admin reads the database directly and never goes
through the cached count. That is what makes this one so confusing.

Most likely trigger: a database-level change that did not go through WooCommerce's own
API, so the cache was never invalidated — e.g. an All-in-One WP Migration restore, a
staging→live push, or a direct DB import. (Plugin was active; exact event not recoverable.)


=============================================================================
THE FIX (about 30 seconds, no code)
=============================================================================
WordPress Admin > WooCommerce > Status > Tools > "WooCommerce transients"
  -> click "Clear transients"   (confirmation reads "Product transients cleared")

That tool also refreshes the shipping transient version, which invalidates the stale
method count. Shipping starts working again immediately — no cache plugin flush, no
re-saving of zones, no plugin deactivation required.

ALTERNATIVE (same effect): open WooCommerce > Settings > Shipping > any zone, edit any
shipping method and re-save it. Saving a method bumps the shipping transient version.

=============================================================================
IF IT EVER HAPPENS AGAIN — 10-SECOND TRIAGE
=============================================================================
1. CANARY: load the checkout with items in the cart. Is the "Ship to a different
   address?" checkbox missing? If yes, shipping is dead store-wide (needs_shipping()
   is false) — it is NOT a zone/LGA/theme problem, so do not start there.
2. FIRST ACTION: WooCommerce > Status > Tools > Clear transients. Re-test.
3. Only if that does not fix it, check in this order:
     - WooCommerce > Settings > General > "Shipping location(s)" is not "Disable
       shipping & shipping calculations"
     - the zones still have enabled methods
     - the cart's products are not marked Virtual (per-variation on variable products)
4. RUN THIS AFTER EVERY migration/restore/DB import — clearing transients is harmless
   (caches simply rebuild) and prevents exactly this failure.

Quick independent check that bypasses the theme completely — needs_shipping must be
true once a physical product is in the cart:
   https://otakustoreng.com/wp-json/wc/store/v1/cart
